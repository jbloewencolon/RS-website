# Relational Sovereignty

Nine routes, no build step at runtime: what ships is what's in this repo, opened straight from disk or served as-is by GitHub Pages. Three different mechanisms produce those nine pages, which is the one thing worth knowing before editing any of them.

## Source map

| Route | You edit | It becomes | How |
|---|---|---|---|
| Manifesto | `hugo/layouts/manifesto.html` | `manifesto/index.html` | `npm run build:hugo` |
| Invitation | `hugo/layouts/invitation.html` | `invitation/index.html` | `npm run build:hugo` |
| Learn | `hugo/layouts/learn.html` | `learn/index.html` | `npm run build:hugo` |
| Archive | `hugo/layouts/archive.html` | `archive/index.html` | `npm run build:hugo` |
| Resources | `hugo/layouts/resources.html` | `resources/index.html` | `npm run build:hugo` |
| Behind the Scenes | `hugo/layouts/behindthescenes.html` | `behind-the-scenes/index.html` | `npm run build:hugo` |
| Home | `index.html` | itself | hand-authored, no build |
| Practise | `practise/index.html` | itself | hand-authored, no build |
| Contribute | `contribute/index.html` | itself | hand-authored, no build |

**The six reading pages are Hugo templates.** `hugo/layouts/*.html` is the source; `npm run build:hugo` renders it through Hugo (a single static binary, no dependency tree) and writes the committed output at the matching repo-root path. Edit the generated `*/index.html` directly and the next build silently overwrites it — edit the template.

**Home, Practise, and Contribute are hand-authored, not Hugo output.** Each carries live interactive logic (forms, a stateful multi-stage tool) that Hugo's static rendering can't hold, so each is a real `.html` file with a `<script type="text/x-dc">` block run by `support.js`, this project's own small dc-runtime. There is no template to build them from — the file in the repo is the file that ships. `support.js` itself is generated by an external toolchain (`dc-runtime/src/*.ts`) that lives outside this repository; never hand-edit it.

**One CSS block is shared across all nine, kept identical three different ways.** `hugo/layouts/partials/head-base.html` is the source. The six Hugo pages pull it in as a partial on every build. The three hand-authored pages can't call a Hugo partial, so `npm run sync:base` renders the same partial and splices its output between `base:start`/`base:end` markers in `index.html`, `practise/index.html`, and `contribute/index.html`, keeping them byte-identical to the Hugo pages' own copy. `npm run check` fails the build if any of the three has drifted from the shared source — that failure means someone edited a spliced copy directly instead of `head-base.html`.

**Everything else at the repo root is either a standalone script or genuinely global.** `sections.js` (pocket/shelf open-state, shared by Learn/Archive/Behind the Scenes), `archive-filter.js`, `notes.js`, `botanical.js` and its per-page companions, and the rest are loaded via `<script src="/…">` from whichever pages use them — no build step touches them; the file in the repo is what ships, same as the three hand-authored HTML pages.

## Build and check

```
npm run build:hugo   # render hugo/layouts/*.html -> repo-root */index.html
npm run sync:base     # splice head-base.html's output into the 3 hand-authored pages
npm run check         # html-validate + axe + mobile/reflow checks + the drift checks above
```

Run `build:hugo` and `sync:base` after any change to `hugo/layouts/partials/head-base.html` or any `hugo/layouts/*.html` file, before `npm run check` — the check suite verifies committed output against source, it doesn't regenerate it.
